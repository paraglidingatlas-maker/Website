# Live site stress test (1 Oct 2026)

The 180 live pages (repo root, the files GitHub Pages serves) were stress-tested in headless Chromium on a local server: paraglidingatlas.com itself is blocked from this environment, so CDN, HTTPS and real-world latency were not tested; slow networks and slow phones were simulated. Nothing in the live site was changed.

Method: one agent per stress area wrote and ran its own tests; a second, independent agent re-ran every finding with its own check and tried to refute it; the CPU and memory pass ran alone so timings were clean; a critic then looked for what had not been covered and tested it. 18 agents in all.

**Result: 83 confirmed problems (4 high, 29 medium, 50 low), 2 refuted, 14 measurements worth knowing.**

Every finding below was reproduced by the second agent. Severity is the verifier's. Re-run any check with its repro command from the repo root (the scripts are in `tools/stress/`; `lib.py` there serves the repo on a port for the run and stops it after; the accessibility checks need `npm install axe-core@4` in `tools/stress`, the print checks `pip install --target tools/stress/degraded/pylib pypdfium2`).
